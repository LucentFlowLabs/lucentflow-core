# LucentFlow 安装部署指南

> **版本：** 1.2.0-STABLE  
> **适用：** 本地 CLI、Docker Compose 全栈、Kubernetes（API / Worker 拆分）  
> **说明：** 本文档汇总操作步骤；密钥与 `.env` 切勿提交到 Git。

---

## 1. 部署形态一览

| 形态 | 适用场景 | 说明 |
|------|----------|------|
| **A. 混合开发** | 日常开发 | Docker 只跑 Postgres（及可选 pgAdmin/Metabase），应用用 `java -jar` |
| **B. Docker Compose 全栈** | 单机 / 演示 / 私有部署 | 一键拉起 Postgres + 应用 + Metabase + pgAdmin |
| **C. Kubernetes 拆分** | 生产雏形 | 同一 Fat JAR：`api` 可水平扩展；`worker` **必须 replicas=1** |

运行时默认单体：同一进程内同时跑 indexer + analyzer + API。可用 Spring Profile 拆分：

| Profile | 命令参数 | 行为 |
|---------|----------|------|
| （默认 / `local` / `docker`） | 无或 `local` | 全开（indexer + analyzer + API） |
| `api` | `--spring.profiles.active=api` | 仅 REST；关闭索引与分析 |
| `worker` | `--spring.profiles.active=worker` | 仅索引+分析；关闭业务 REST（保留 Actuator） |

---

## 2. 环境要求

| 组件 | 版本 | 用途 |
|------|------|------|
| JDK | **21+**（需 Virtual Threads） | 运行与构建 |
| Maven | **3.9+** | 构建 Fat JAR |
| Docker / Compose | Compose **V2（建议 ≥ 2.20）** | 基础设施与全栈部署 |
| PostgreSQL | **16**（Compose 镜像已带） | 主存储 / Flyway / 共享限流与 lease |
| kubectl（可选） | 与集群版本匹配 | K8s 部署 |

校验：

```bash
java -version          # 期望 openjdk 21.x
mvn -v                 # 期望 3.9+
docker compose version # 期望 v2.x
```

Windows 可用 PowerShell 或 Git Bash；仓库根目录提供 `start-infrastructure.ps1` / `start-infrastructure.sh`。

---

## 3. 构建产物

在仓库根目录执行：

```bash
mvn clean package
```

成功后：

- 可执行 Fat JAR：`lucentflow-api/target/lucentflow-api-*.jar`
- 镜像到仓库根：`./lucentflow.jar`（便于 `java -jar`）

启动前 **必须** 提供 `POSTGRES_PASSWORD`（环境变量或 `.env`），否则进程会主动失败退出。

---

## 4. 配置文件（.env）

### 4.1 准备

```bash
# 推荐：仓库根一份操作员覆盖配置
cp lucentflow-deployment/docker/.env.example .env

# 或仅在 Docker 目录使用
cp lucentflow-deployment/docker/.env.example lucentflow-deployment/docker/.env
```

`AdaptiveEnvLoader` 按顺序合并（**先出现的键优先**）：

1. `./.env`（仓库根）
2. `./lucentflow-deployment/docker/.env`
3. `../lucentflow-deployment/docker/.env`（从子模块目录启动时）

已存在的 OS 环境变量 / JVM `-D` **不会被 `.env` 覆盖**（适合 K8s Secret）。

### 4.2 必填 / 常用项

| 变量 | 必填 | 说明 |
|------|------|------|
| `POSTGRES_PASSWORD` | **是** | 数据库密码 |
| `POSTGRES_DB` / `POSTGRES_USER` | 建议 | 默认 `lucentflow` / `admin` |
| `DB_HOST` | 本地 CLI 时 | 默认 `localhost`；Compose 内应用用服务名 `postgres` |
| `LUCENTFLOW_CHAIN_RPC_URL` | 建议 | Base JSON-RPC；默认官方 `https://mainnet.base.org` |
| `LUCENTFLOW_CHAIN_RPC_BACKUP_URL` | 可选 | 主端点非 429 故障时切换 |
| `BASESCAN_API_KEY` | 深度溯源建议 | Genesis Trace / Basescan |
| `LUCENTFLOW_INDEXER_START_BLOCK` | 可选 | 无 checkpoint 时的起始块 |
| `LUCENTFLOW_ADMIN_API_KEY` | B2B 管理 | Admin API `X-Admin-Key` |
| `TELEGRAM_*` / `LUCENTFLOW_DISCORD_WEBHOOK_URL` / `LUCENTFLOW_WEBHOOK_*` | 可选 | 告警通道 |
| `PROXY_HOST` / `PROXY_PORT` | 可选 | 映射为 JVM `http(s).proxy*` |

### 4.3 配额与限流（集群共享分钟桶）

| 变量 | 默认 | 说明 |
|------|------|------|
| `LUCENTFLOW_API_DAILY_REQUEST_QUOTA` | `100000` | 项目日配额；`0` 关闭 |
| `LUCENTFLOW_API_RATE_LIMIT_PER_MINUTE` | `120` | 项目分钟限流（PG 共享）；`0` 关闭 |
| `LUCENTFLOW_API_PUBLIC_RATE_LIMIT_PER_MINUTE` | `60` | 公开接口按 IP；`0` 关闭 |

### 4.4 Lease 选主（Worker）

| 变量 | 默认 | 说明 |
|------|------|------|
| `LUCENTFLOW_LEASE_ENABLED` | `true` | 关闭后本进程视为永久 leader（仅本地/测试） |
| `LUCENTFLOW_LEASE_TTL_SECONDS` | `15` | lease TTL |
| `LUCENTFLOW_LEASE_RENEW_INTERVAL_SECONDS` | `5` | 续约间隔 |

> **重要：** Lease 是防御纵深，**不能**替代「worker 副本数 = 1」的部署门禁。未完成多副本故障切换验证前，禁止 `kubectl scale` worker。

### 4.5 付费 RPC 调参

仅当 `LUCENTFLOW_CHAIN_RPC_URL` **不是** `mainnet.base.org` 时，`.env` 中的 batch / concurrency 等调参才会生效。官方公共 RPC 使用内置安全节奏，避免打爆公共节点。

## 5. 形态 A：混合开发（推荐日常）

### 步骤 1 — 启动基础设施

```bash
# Linux / macOS / Git Bash
./start-infrastructure.sh

# Windows PowerShell
.\start-infrastructure.ps1
```

或手动：

```bash
cd lucentflow-deployment/docker
docker compose up -d postgres
# 可选：docker compose up -d pgadmin metabase
```

等待 Postgres healthy：

```bash
docker compose -f lucentflow-deployment/docker/docker-compose.yml ps
```

### 步骤 2 — 配置并启动应用

```bash
cd <仓库根目录>
cp lucentflow-deployment/docker/.env.example .env
# 编辑 .env：至少设置 POSTGRES_PASSWORD；DB 指向 localhost:5432

mvn clean package
java -jar lucentflow.jar
```

未设置 `SPRING_PROFILES_ACTIVE` 且不在容器内时，加载器会自动使用 `local`。  
若 `.env` 中 `PROXY_HOST=host.docker.internal`，在 `local` 下会改写为 `127.0.0.1`。

### 步骤 3 — 验证

```bash
curl http://localhost:8080/actuator/health
curl http://localhost:8080/api/v1/sync-status
```

浏览器：

- Swagger：http://localhost:8080/swagger-ui/index.html  
- Metabase（若已起）：http://localhost:3000  
- pgAdmin（若已起）：http://localhost:5050  

### 步骤 4 —（可选）加载演示租户数据

**仅本地/演示，禁止生产执行：**

```bash
psql -h localhost -U admin -d lucentflow -f lucentflow-api/src/main/resources/db/demo_setup.sql
```

演示项目 Key：`X-Project-Key: demo-project-key-2026`（以 `demo_setup.sql` 为准）。

生产请用 Admin API 创建项目并轮换密钥；Flyway **V1** 起库内仅存 `api_key_hash`（SHA-256），无明文 bootstrap key。

## 6. 形态 B：Docker Compose 全栈

### 步骤 1 — 配置

```bash
cd lucentflow-deployment/docker
cp .env.example .env
# 修改 POSTGRES_PASSWORD、RPC、BASESCAN_API_KEY、LUCENTFLOW_ADMIN_API_KEY 等
```

### 步骤 2 — 构建并启动

```bash
docker compose up --build -d
```

### 步骤 3 — 健康检查

```bash
docker compose ps
curl http://localhost:8080/actuator/health
```

### 步骤 4 — 常用运维

```bash
docker compose logs -f lucentflow-api
docker compose restart lucentflow-api
docker compose down          # 停服务（保留 volume）
docker compose down -v       # 危险：清数据卷
```

Schema 由应用内 **Flyway** 在启动时迁移（`ddl-auto: none`），无需手工建表。

## 7. 形态 C：Kubernetes（API + Worker）

同一镜像、不同 Profile。清单目录：`lucentflow-deployment/k8s/`。

### 7.1 硬性约束（单写者 Worker）

PostgreSQL TTL 租约（`worker_leases` / `WorkerLeaseCoordinator`）已会门禁 indexer 扫描与 analyzer 消费；**本版本部署策略仍不变**：在完成多副本故障切换验证前，worker **只能 1 副本**。租约是纵深防御，不是放行多写者的绿灯。

1. `lucentflow-worker.spec.replicas` **必须为 1**
2. 滚动策略 **必须为 `Recreate`**（禁止 RollingUpdate 双写窗口）
3. **不要** 为 worker 创建 Service / Ingress
4. 必须应用 `networkpolicy.yaml`（拒绝他 Pod 访问 worker:8080）
5. **禁止** 对 worker 做 `kubectl scale` / HPA

违反仍可能在租约过期窗口内出现重叠写者，损坏 `sync_status` **ID=1**。

部署前断言（CI 也会跑）：

```bash
python3 lucentflow-deployment/k8s/assert_single_writer.py
# Windows:
py lucentflow-deployment/k8s/assert_single_writer.py
```

### 7.2 构建镜像

仓库根 `Dockerfile`（多阶段 Maven + Temurin 21）：

```bash
docker build -t lucentflow/lucentflow-api:1.2.0-STABLE .
# 推送到你的仓库后，按需改 deployment.yaml 中的 image
```

### 7.3 创建 Secret / 应用清单

```bash
kubectl create secret generic lucentflow-secrets \
  --from-literal=POSTGRES_PASSWORD='<强密码>' \
  --from-literal=LUCENTFLOW_ADMIN_API_KEY='<管理员密钥>' \
  --from-literal=SPRING_DATASOURCE_URL='jdbc:postgresql://postgres:5432/lucentflow'

cd lucentflow-deployment/k8s
kubectl apply -f configmap.yaml
kubectl apply -f networkpolicy.yaml
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
```

| 工作负载 | Profile | 角色 | 副本 |
|----------|--------|------|------|
| `lucentflow-api` | `api` | REST + Actuator | 可扩展 |
| `lucentflow-worker` | `worker` | 索引 + 分析 | **恰好 1** |

### 7.4 集群内校验

```bash
kubectl get deploy lucentflow-worker -o jsonpath='{.spec.replicas}{"\n"}{.spec.strategy.type}{"\n"}'
# 期望：1 / Recreate

kubectl get svc -l component=worker
# 期望：空

kubectl get networkpolicy lucentflow-worker-deny-ingress
kubectl logs -l component=worker --tail=100
kubectl port-forward svc/lucentflow-api 8080:8080
curl http://localhost:8080/actuator/health
```

> Actuator 在组件 DOWN 时仍可能返回 HTTP 200（便于部分探针）；探活请解析 JSON body，勿只看状态码。

## 8. 进程拆分（非 K8s 时）

同一 JAR：

```bash
# 仅 API
java -jar lucentflow.jar --spring.profiles.active=api

# 仅 Worker（全集群仍只能有一个写进程）
java -jar lucentflow.jar --spring.profiles.active=worker
```

或用环境变量：

```bash
export LUCENTFLOW_RUNTIME_ENABLE_INDEXER=false
export LUCENTFLOW_RUNTIME_ENABLE_ANALYZER=false
# API 侧

export LUCENTFLOW_RUNTIME_ENABLE_API=false
# Worker 侧（并确保 indexer/analyzer=true）
```

## 9. 上线后检查清单

- [ ] `POSTGRES_PASSWORD` 已设置且非默认弱口令  
- [ ] Flyway 迁移成功（日志无 checksum / 迁移失败）  
- [ ] `/actuator/health` 可访问；`/api/v1/sync-status` 有合理 `last_scanned_block`  
- [ ] 官方 RPC 未误开激进 concurrency；付费 RPC 已单独调参  
- [ ] 生产未执行 `demo_setup.sql`  
- [ ] 已设置 `LUCENTFLOW_ADMIN_API_KEY`；项目 Key 仅通过 Admin API 发放  
- [ ] K8s：worker replicas=1、Recreate、无 worker Service、NetworkPolicy 已应用  
- [ ] 单写者门禁脚本通过：`assert_single_writer.py`

## 10. 常见问题

| 现象 | 处理 |
|------|------|
| 启动立即退出，提示缺密码 | 设置 `POSTGRES_PASSWORD` |
| 429 / RPC 过慢 | 换付费 RPC，或降低 concurrency；官方 RPC 勿强行调高 |
| 本地代理不通 | `local` 下确认 `host.docker.internal` 已被改写为 `127.0.0.1` |
| sync 进度异常 / 双写 | 检查是否多 worker；立刻缩回 1 并核对 lease / checkpoint |
| 公开接口被限流 | 调整 `LUCENTFLOW_API_PUBLIC_RATE_LIMIT_PER_MINUTE` 或 `0` 关闭（不推荐生产关闭） |
